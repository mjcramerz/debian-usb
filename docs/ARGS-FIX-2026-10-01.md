# Explicit preseed arguments: runtime restriction removed

## Fixed behavior

The supplied `PRESEED_FIVE_ARGS_DEBIAN_DE` assignment now loads successfully in
both the Go runtime and Python helper. Explicit `netcfg/choose_interface`,
`netcfg/wireless_essid`, `netcfg/wireless_essid_again`,
`netcfg/wireless_security_type`, and `netcfg/wireless_wpa` values are retained.
No migration to `initrd/debian/live/live.env` is required for these arguments.

The old name-based Live Wi-Fi and legacy-secret deny lists have been removed
from configuration validation and boot argument rendering. This is not a
single-preset exception: common arguments, numbered presets, transport args,
profile overrides, hook args, and custom argument fields retain explicit
values. Additional keys containing `_ARGS_` or ending in `_ARGS` or
`_KERNEL_EXTRAS` also survive settings load/save, rather than being discarded.
Custom keys still need a matching GRUB spec reference to create menu entries.

GRUB metacharacters are escaped instead of rejecting valid values. Live ISO
remastering now accepts these argument names and printable punctuation, escapes
arguments on GRUB `linux`/`linuxefi`/`linux16` lines, and preserves literal
Syslinux `append` values. Control characters other than normal argument
whitespace remain invalid. Existing seed-transport selection, boot-mode
precedence, mandatory hook selectors, and non-argument validation are unchanged.

The managed initrd env-file workflow remains intact and does not automatically
inject secrets into kernel arguments. Explicit command-line values are visible
in the generated boot configuration and kernel command line. The separate
`secrets.sh` cleanup and Git secret-management tooling are unchanged.

All original configuration assignments, including the reported fifth Debian
preset, are preserved byte-for-byte. Only explanatory configuration comments
were updated. Every original file is included in the archive; the bundled CLI
has been replaced with a fresh build from the repaired source.

## Toolchain and reproduction

The available compiler was Go 1.23.2. Downloading the declared Go 1.24.0 toolchain
was unavailable, so tests and the included static Linux amd64 executable used
an external temporary modfile changing only the Go version directive. The
repository `go.mod` was not changed. Python tests used Python 3.13.5.

With Go 1.24.0 or newer, the normal commands remain:

```sh
make check
go test -race ./...
go vet ./...
make build
```

The equivalent local compatibility run used:

```sh
tmpdir=$(mktemp -d)
trap 'rm -rf "$tmpdir"' EXIT
sed 's/^go 1.24.0$/go 1.23.2/' go.mod > "$tmpdir/local.mod"
export GOTOOLCHAIN=local
export GOFLAGS="-modfile=$tmpdir/local.mod"
make check
go test -race ./...
go vet ./...
CGO_ENABLED=0 go build -trimpath -o build/debian-usb ./cmd/debian-usb
```
